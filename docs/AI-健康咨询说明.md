# AI 健康咨询功能说明

> 本文档严格依据 [health_consultation.vue](../src/pages/home/health_consultation.vue) 和 [health_consultation_history.vue](../src/pages/home/health_consultation_history.vue) 两个前端页面编写，仅描述这两个页面中已经实现的功能、交互和接口。

## 1. 页面范围

该功能由两个页面组成。

1. [健康咨询聊天页](../src/pages/home/health_consultation.vue)：负责 AI 对话、消息发送、思考过程展示、历史会话进入后的会话恢复。
2. [健康咨询历史页](../src/pages/home/health_consultation_history.vue)：负责历史会话列表展示、进入既有会话、删除会话、发起新对话。

这两个页面都基于 `uni-app` 和 Vue 3 `<script setup>` 实现，接口统一使用 `BASE_URL` 拼接后端地址。

## 2. 聊天页功能

### 2.1 首次进入与欢迎态

当当前会话没有任何消息时，页面展示欢迎内容，包括：

1. 机器人头像和欢迎语“你好，我是健康咨询助手”。
2. 功能描述“基于你的健康档案，为你提供个性化饮食与运动建议”。
3. 问卷未填写提示卡片，仅在 `questionnaireCompleted !== 'true'` 时显示。
4. 快捷提问列表。
5. 右上角历史会话入口按钮，仅在空会话时显示。

### 2.2 问卷状态控制

页面会在 `onLoad` 和 `onShow` 时读取本地存储 `questionnaireCompleted`，并据此控制模板提问能力。

1. 当值为 `true` 时，快捷问题可直接发送。
2. 当值不是 `true` 时，快捷问题会弹窗提示用户先去填写问卷。
3. 即使未填写问卷，用户仍然可以手动输入自定义问题并发送。

### 2.3 快捷问题

页面内置了 5 条快捷提问，其中第一条是较长的模板提示词，内容要求 AI 严格按“饮食方案”和“运动计划”格式输出。

快捷问题的行为如下：

1. 点击后会将问题填入输入框。
2. 若问卷未填写，则不发送，改为弹窗提示。
3. 若问卷已填写，则直接调用发送逻辑。

### 2.4 消息展示

聊天记录以列表形式渲染，每条消息包含角色、内容、局部状态和展示样式。

1. 用户消息显示在右侧，使用用户头像。
2. AI 消息显示在左侧，使用机器人图标。
3. AI 消息支持“思考过程”折叠展示。
4. AI 回复支持自动换行和简单 Markdown 清理。

消息支持的状态包括：

1. `role`：`user` 或 `assistant`。
2. `content`：正式回复内容。
3. `thinking`：思考过程文本。
4. `loading`：是否处于加载中。
5. `_thinkingLoading`：是否显示思考动画。
6. `_showThinking`：是否展开思考过程。

### 2.5 思考过程展示

AI 回复在等待接口返回时，会显示一个“思考中”卡片，并通过定时器轮换以下文案：

1. 正在分析问题
2. 正在结合健康档案
3. 正在组织建议结构

加载完成后，若后端返回了 `thinking` 字段，则会以可展开卡片的形式展示；用户点击卡片头部可以切换展开与收起。

### 2.6 输入与发送

底部输入区由文本框、字数提示和发送按钮组成。

1. 输入框最大 500 字。
2. 输入框支持 `confirm-type="send"`，可直接回车发送。
3. 发送按钮在输入为空或正在请求中时置为不可用状态。
4. 发送后会先把用户消息追加到消息列表，再插入一个 AI 加载气泡。

### 2.7 登录校验

发送消息前会先检查本地 `token`。

1. 如果没有 token，会弹出登录提示框。
2. 用户确认后可跳转到登录页 `/pages/login/login`。
3. 未登录时不能发起 AI 请求。

### 2.8 会话创建与标题更新

聊天页支持新会话和历史会话两种进入方式。

1. 如果没有传入 `sessionId`，页面视为新会话。
2. 如果从历史页带入 `sessionId`，页面会加载该会话历史。
3. 第一次成功返回 AI 数据后，如果当前还没有 `currentSessionId`，前端会保存后端返回的 `sessionId`。
4. 新会话的导航栏标题会被更新为当前问题的前 15 个字符，超出部分用省略号截断。

### 2.9 历史会话恢复

当页面接收到 `sessionId` 时，会调用历史接口恢复消息列表。

1. 会话标题优先使用路由参数 `title`。
2. 如果未传标题，默认显示“历史对话”。
3. 成功后会把接口返回的消息数组映射为前端消息结构。
4. 恢复完成后自动滚动到底部。

### 2.10 错误与超时处理

页面对 AI 请求做了基本的异常处理和重试。

1. 请求如果遇到超时类错误，会自动重试一次。
2. 如果重试仍失败，会在加载气泡中显示“AI响应超时，可能已生成，请在历史中查看”或“网络异常，请检查网络后重试”。
3. 如果服务端状态码大于等于 400，会显示“服务器繁忙，请稍后再试”。
4. 如果接口返回非 200 业务码，会显示后端返回的 message 或 msg。

### 2.11 回复内容处理

前端对 AI 返回文本做了统一清洗。

1. 把转义换行 `\\n`、`\\r\\n`、`\\r` 转成真实换行。
2. 去除 `<think>` 标签内容和标签本身。
3. 去掉 Markdown 标题前缀 `#`。
4. 去掉 Markdown 分隔线。
5. 去掉粗体标记 `**`。
6. 合并过多空行并去首尾空白。

思考内容也会做类似换行和标签清理，但不会清除标题或粗体标记之外的内容。

### 2.12 自动滚动

每次新增消息、更新消息或加载历史后，页面都会尝试滚动到底部锚点 `msg-bottom`，保证最新回复始终可见。

## 3. 历史页功能

### 3.1 历史列表展示

历史页在 `onShow` 时从后端重新拉取会话列表。

1. 如果没有 token，列表直接置空。
2. 接口成功并返回数组时，列表按接口数据渲染。
3. 如果接口失败或返回格式不正确，会清空列表并提示错误。

空状态下会显示“暂无历史会话”，并提示用户返回 AI 对话页面开始新对话。

### 3.2 会话列表项

每个会话项展示以下信息：

1. 会话图标。
2. 会话标题，未提供时显示“新对话”。
3. 最后时间 `lastTime`。
4. 进入箭头。
5. 删除按钮。

### 3.3 打开历史会话

点击任意会话项，会跳转到聊天页并带上参数：

1. `sessionId`
2. `title`

聊天页收到这些参数后，会加载对应会话历史。

### 3.4 删除会话

点击删除按钮会弹出确认框。

1. 确认后才会调用删除接口。
2. 删除成功后，前端会把该会话从列表中移除。
3. 删除成功时会提示“已删除”。
4. 若删除失败，会展示接口 message 或通用错误提示。

### 3.5 开始新对话

底部按钮“开始新对话”会直接跳转到聊天页，不携带 `sessionId`，因此会打开一个新的空对话。

## 4. 使用到的本地状态

### 4.1 聊天页状态

1. `messages`：消息列表。
2. `inputText`：输入框内容。
3. `isLoading`：发送请求中标记。
4. `scrollTarget`：滚动锚点。
5. `hasQuestionnaire`：问卷完成状态。
6. `currentSessionId`：当前会话 ID。
7. `currentSessionTitle`：当前会话标题。
8. `isFromHistory`：是否从历史页进入。
9. `userAvatar`：用户头像路径。

### 4.2 历史页状态

1. `sessions`：历史会话列表。

## 5. 本地存储依赖

页面使用了以下本地存储键。

1. `token`：登录态令牌，用于调用 AI 与历史接口。
2. `userInfo`：用户头像来源之一，页面启动时会尝试读取其中的 `avatar`。
3. `questionnaireCompleted`：问卷完成标记，用于控制快捷提问是否可直接使用。
4. `myPlan`：AI 返回饮食方案与运动方案后，会同步写入本地缓存。

## 6. 后端接口依赖

这两个页面当前实际调用的接口只有以下 4 个。

### 6.1 发送 AI 对话

- 方法：`POST`
- 地址：`/api/ai/chat`
- 请求头：
  - `Authorization: Bearer <token>`
  - `Content-Type: application/json`
- 请求体：
  ```json
  {
    "sessionId": "当前会话ID，首次发送时可以为空字符串",
    "message": "用户输入内容"
  }
  ```
- 成功处理：
  - 业务码为 `200` 时视为成功。
  - 返回数据会写入当前消息气泡。
  - 如果返回中包含 `sessionId`，前端会保存到 `currentSessionId`。
  - 如果返回中包含 `diet` 或 `exercise`，或者 `content` 中能解析出“饮食方案 / 运动计划”区块，前端会同步缓存到 `myPlan`。

### 6.2 获取会话列表

- 方法：`GET`
- 地址：`/api/ai/sessions`
- 请求头：`Authorization: Bearer <token>`
- 成功后返回会话数组，用于历史页渲染。

### 6.3 获取会话历史

- 方法：`GET`
- 地址：`/api/ai/sessions/{sessionId}/history`
- 请求头：`Authorization: Bearer <token>`
- 成功后返回消息数组，用于聊天页恢复历史消息。

### 6.4 删除会话

- 方法：`DELETE`
- 地址：`/api/ai/sessions/{sessionId}`
- 请求头：`Authorization: Bearer <token>`
- 成功后前端会立刻从历史列表中移除该会话。

## 7. AI 回复中的方案缓存逻辑

聊天页内置了一个针对健康方案的缓存同步逻辑，目的是把 AI 生成的饮食/运动方案保存到本地 `myPlan`。

### 7.1 支持的内容来源

前端会优先从接口返回的这些字段中提取方案：

1. `data.diet`
2. `data.exercise`
3. `data.content` 中按以下区块格式提取：
   - `【饮食方案开始】...【饮食方案结束】`
   - `【运动计划开始】...【运动计划结束】`
   - `【运动方案开始】...【运动方案结束】`

### 7.2 缓存写入规则

1. 如果能提取到饮食或运动内容，就会写入本地 `myPlan`。
2. 写入时会保留原有缓存中的其他字段。
3. 如果本次只返回了饮食或只返回了运动，另一个字段会尽量沿用已有缓存值。

## 8. 页面交互细节

### 8.1 头像处理

1. 用户头像优先读取本地 `userInfo.avatar`。
2. 如果头像加载失败，会回退到 `/static/logo.png`。

### 8.2 消息键值

列表渲染时使用 `_localId` 作为消息的本地唯一键，避免渲染抖动。

### 8.3 底部输入区行为

1. 输入区固定在页面底部。
2. 发送按钮会根据内容和加载状态切换可用状态。
3. 字数提示始终显示当前输入长度与上限。

## 9. 现有页面行为总结

如果把这两个页面串起来，完整使用流程是：

1. 用户进入健康咨询聊天页。
2. 页面根据是否有历史消息决定展示欢迎页或聊天记录。
3. 若已填写问卷，用户可以直接点击快捷提问；否则只能自定义提问或先去填写问卷。
4. 用户发送消息后，页面显示 AI 加载态和思考过程。
5. 返回结果后，前端清洗文本并展示，同时根据内容更新本地方案缓存。
6. 用户可以进入历史页查看全部会话。
7. 历史页支持重新打开某个会话，也支持删除会话或直接开始新对话。

## 10. 说明边界

本文档不描述以下内容，因为它们不在这两个前端文件中实现：

1. 图片识别。
2. 语音输入。
3. 附件上传。
4. 流式返回。
5. 复杂的多轮上下文编辑界面。
6. 除当前四个接口外的其他 AI 接口。

文档结束。
